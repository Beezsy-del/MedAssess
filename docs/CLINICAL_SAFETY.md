# Clinical safety boundary

- Synthetic data only. No clinical validation, diagnostic accuracy or operational suitability is claimed.
- Emergency guidance is available without an account. Patient token holders can request immediate staff assistance without completing intake. The website is not an emergency dispatch service.
- Missing and unverified information stays explicit. All ordinary automated recommendations require human assessment.
- Clinical urgency outranks numerical score. Resource shortages never reduce urgency.
- Overrides retain the original recommendation and require a reason. Active emergencies cannot be downgraded by a nurse.
- All care-state changes are validated, attributed and timestamped. Discharge requires a doctor; admission requires a reserved bed.
- Offline capture is device-local. It cannot notify other disconnected devices. Use a manual register and direct communication during outages.
- Kannada/Hindi strings are prototype translations requiring qualified review. Voice recognition output is editable, patient-reported text, not a confirmed finding.
- All hospital records currently represent demo operations. Real clinical workflows are disabled by database policy and constraints.

Before real deployment: obtain local clinical governance approval, reviewed protocol sources and translations, role/department access design, privacy/legal review for the deployment jurisdiction, data-retention policy, independent security assessment, downtime procedures, staff training and operational acceptance testing. No such approvals have been obtained in this implementation.

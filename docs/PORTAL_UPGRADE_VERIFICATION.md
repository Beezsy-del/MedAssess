## Environment and migration status

The local application uses a real isolated Supabase stack (PostgreSQL, Auth, PostgREST and Realtime), not mocked successful API calls. Two synthetic hospital tenants and separate nurse, doctor, receptionist, administrator, resource and emergency accounts are seeded through `scripts/prepare-local.mjs`. Local-only scripts reject non-loopback database URLs. Credentials are stored in ignored, owner-readable files and are never committed.

All 16 migrations were applied locally. The two new portal/workflow migrations also replay against the existing 14-migration baseline in a transaction that executes the SQL assertions and rolls back. Both new migrations have now been applied to the existing hosted project. Production is https://medcipher-triage-platform.vercel.app/. The tested preview and exact deployment evidence are recorded in PORTAL_RELEASE.md.

## Local viewing and repeatable setup

The running local build is at http://localhost:3011/ (same machine). Use the demo role buttons; local credentials are not needed in this report. A different computer cannot use this localhost URL.

For a fresh local checkout, install pinned npm dependencies, start Docker, and run the pinned Supabase start command in `.github/workflows/ci.yml`. Capture `supabase status -o env` into an owner-readable temporary file; run `node scripts/prepare-local.mjs` once. Reuse the resulting ignored `.env.local-test` and `.demo-local-fixture.json`; do not repeatedly seed or reset a hosted database. Run commands through `node scripts/run-local.mjs`, including `scripts/portal-check.mjs` before browser acceptance to install the explicitly synthetic protocol fixture. Build with `node scripts/run-local.mjs node_modules/next/dist/bin/next build`; start with the same runner and `next start --port 3011`. The CI workflow contains the complete repeatable sequence.

The local Colima VM is named `medcipher`. Keep it running while viewing the app. To stop after use, stop the local Next server and run `npx --yes supabase@3.2.0 stop`, then `colima stop medcipher`. Do not stop unrelated local servers.

## Clean-start Realtime correction

The first GitHub run for `da4bfdb` passed static/build verification and every database workflow group, but its first Realtime delivery timed out. An isolated fresh local stack reproduced the exact failure; a second subscription on the same warmed stack passed. The installed SDK documents that ordinary `SUBSCRIBED` can precede the actual Postgres subscription. Both the workspace and the regression script now use `postgres_changes_options.wait: true`, so subscription acknowledgement waits for the change stream. The cold-start delivery and disconnect/reconnect checks then passed on the freshly rebuilt local stack. The public table publication and RLS were retained unchanged; no test was disabled or weakened.

During reproduction the main local synthetic stack was accidentally stopped without a backup. Its synthetic fixtures were rebuilt from the committed seed script and verification was repeated; no hosted database or real patient data was involved. The separate temporary reproduction stack was stopped afterward.
